# A100 pilot: original failure and separate math-SDPA strict pass

The original default-runtime pilot failed strict correctness. A separately declared process-wide math-SDPA runtime later passed all six zero-tolerance checks on the same one development clip. No quality or performance result is accepted.

On October 27, 2026, an A100 SXM4 80 GB exploratory pilot failed the unchanged exact numerical checks (`atol=0`, `rtol=0`). The environment checks passed, including real CUDA execution, native sm80 attention smoke tests, a CUDA trace and SM counters. The numerical result stopped the sequence before the separate conditioning-all check or either timing pilot.

This covers **one nuScenes development clip**, two serial action-conditioned candidates, 25 total frames (one observed and 24 generated), 576×1024 resolution and 50 denoising steps. Source, inputs and runtime remained unchanged; the diagnostic did not time out. There is **no accepted latency, speedup, tail-latency, headline or quality-preservation result**. The prepared four-future continuation is blocked.

Errors use the saved normalized float32 outputs, including all 25 frames. The two rightmost columns are separate maxima over the candidates in each check; they are not pooled or mean errors. Cache-key invalidation and actual image-embedding/posterior-parameter cache-hit checks passed, while output equality failed.

Three equivalent uncached normal executions, each using a freshly loaded engine with the same actions, seeds and generation settings, also differed. All six candidate comparisons across the three run pairs were unequal: maximum absolute errors ranged from **0.106935 to 0.218067**, and RMSE from **0.002035 to 0.002878**. These are repeated observations of the same clip, not six independent scenes. They establish an uncached repeatability failure without requiring a cache or candidate-order change. They do not identify its hardware or algorithmic cause.

The recorded runtime used PyTorch 2.0.1+cu118, cuDNN 8.7 and xFormers 0.0.20 built for sm80. Deterministic algorithms were disabled; cuDNN TF32 was enabled and matmul TF32 was disabled. These settings are evidence, not a causal diagnosis. A separately archived first-step diagnostic narrows the observed divergence to before denoising, as described below; it does not turn the failed full-generation proof into a pass.

A verified first-step diagnostic constructed the same seeded input twice and replayed one captured input through the first denoiser three times. All three resident replays were exactly equal, with unchanged inputs and CPU/CUDA RNG states. The two input constructions already differed in the observed-frame latent: **68,086 of 1,843,200 values**, maximum absolute error **0.0000602007**, RMSE **0.000000712041**. Differences occurred only at leading indices 0 and 25, the same observed frame duplicated across the two classifier-free-guidance halves. The five other input tensors, remaining latent indices and CPU/CUDA RNG states were exact. This localizes the observed divergence before the first denoiser call; it does not identify a particular kernel or establish full-generation repeatability. The diagnostic performed no complete sampler rollout or decoding. Its 16-file, 53,848,669-byte archive was hash-verified, including an independent rehash for this projection.
