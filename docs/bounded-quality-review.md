# Bounded quality execution and native review preservation

`scripts/run_quality_bounded.py` is a standalone wrapper around the frozen study runner. It does not change model code, manifests, the immutable plan, selected policies or core generation. Its three temporary in-process hooks restore in `finally`. The benchmark and evaluator remain separate subprocesses, using their original environments.

The wrapper permits a new uncompleted benchmark only when the declared complete-variant bound plus a minimum 240-second cleanup margin fits before an explicit UTC deadline. The complete-variant bound must include model loading, warmups, generation, both reference comparisons, and native export. Each new evaluator and each new native export receives another admission check. `--max-new-runs` pauses before the next new benchmark after the requested number of new benchmarks have completed; completed and adopted receipts do not consume that count. An already generated variant's metrics and export finish before the next variant is considered. A resumed metric with a missing native export must pass export admission again.

These bounds must be chosen conservatively from measured job durations. They are admission bounds, not evidence that a subprocess cannot overrun. The external allocation watchdog and bounded host launcher remain mandatory. Do not choose an allocation deadline later than the actual guard. A deliberate pause returns exit 0 with `status: intentionally_paused` and `phase_complete: false`; it must not be called a completed phase. Every invocation writes a new private execution receipt, including source/plan checksums, bounds, counts, native export receipt hashes and the pause/result status. Unexpected failures preserve their error type and re-raise. Use a fresh execution-receipt filename on resume.

```sh
python scripts/run_quality_bounded.py \
  --study outputs/full-study \
  --phase development \
  --deadline-utc '<actual allocation deadline in UTC>' \
  --run-budget-seconds '<conservative complete variant bound>' \
  --evaluation-budget-seconds '<one comparison bound>' \
  --export-budget-seconds '<one native export bound>' \
  --max-new-runs 1 \
  --receipt outputs/quality-execution-001.json
```

The placeholders are required planning inputs, not suggested numeric defaults. Use the same `--adopt NAME=PATH` and `--adoption-source NAME=PATH` bindings as the study runner for existing bootstrap runs. `--runtime-config PATH` accepts only the existing quality runtime overlay, with a verified replacement environment identical except for GPU UUID/PCI address. Timing comparisons still require one full GPU identity and use the separate timing companion. `--max-shards` retains the core shard meaning; it is not a variant count.

Before core raw retirement, every completed comparison involving that run is checked against the original metric receipt. The wrapper reads the private mapping inside the process, verifies every selected NPY against the run's committed output hash, and exports every future frame with the original opaque case ID and A/B mapping. A PNG pair contains both panels at their original width and height with a separate label strip. The conversion is the existing `round(float32 × 255)` display conversion. PNG is lossless for these display pixels; it does not preserve the original float32 values. The blind index links pages of twelve ordered frame pairs arranged three by four at native panel width, plus individual PNGs. It never exposes run labels or source paths. This supports agent-assisted ordered-frame inspection; it does not establish real-time playback or human review.

Exports live at `quality/PHASE/native-review/OPAQUE_BUNDLE/public/`. Only that `public` directory is suitable for blinded reviewers. Its sibling `private-receipt.json` is created with mode 0600 and binds source arrays, original metric/review artifacts, wrapper SHA and every public file hash. Reviewers must not open the private receipt or original private key before sealing votes. Record votes in a separate CSV; the exported original blank CSV and original review files remain immutable.

The export is built privately, synchronized and atomically committed before any raw deletion. A missing/changed source, changed metric/key, incomplete export, altered PNG, or insufficient disk reserve prevents deletion. A valid existing export is rehashed on resume; if its original NPY still exists it is rehashed too. An NPY missing after a previously sealed retirement can be accepted only with the matching complete export. Existing original metric/review receipts are never rewritten. Wrapper receipts bind the native receipt hashes for external archival verification.

The original core still decides which raw files are eligible for retirement and which selected raw arrays remain. Adopted bootstrap arrays are preserved. Native PNGs add substantial disk use: four cases of 24 frame pairs are about 0.316 GiB of RGB pixels before PNG compression and labels. The wrapper reserves a conservative PNG upper bound plus the plan's free-space reserve before writing. Archive completed diagnostics and completed export bundles only with independently verified hashes and exact-path restoration instructions; a later wrapper resume requires its exports to be present. Bind the wrapper's exact SHA in the bounded host specification. Run the synthetic wrapper tests before deployment; synthetic tests establish orchestration behavior, not model quality or performance.

Enable `--upstream-ground-truth` from the first invocation when recorded-future proxies for the upstream reference are required. Before retiring each reference shard, the wrapper invokes the separately versioned CPU-only `export_recorded_ground_truth.py`. Its exclusive JSON/receipt pair binds the complete recorded-action request coverage, manifest, source NPYs and dataset-image hashes. Existing committed exports are revalidated and must belong to the same run; missing previously retired arrays remain explicitly unavailable raw evidence. Missing or partial exports cannot authorize deletion. A new GT export must also fit the declared export-time bound. The wrapper receipt binds the GT helper SHA and both output/receipt hashes. This computes numeric recorded-future proxies, not extra LPIPS or a new quality gate. Adding this flag after earlier raw retirement may require restoring arrays first.
